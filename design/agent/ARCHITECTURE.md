# Agent 系统架构设计

## 架构总览

Agent 系统是 Cradle 的核心，采用**三层架构**设计，实现职责分离和任务编排能力。

### 三层架构

## Agent 核心设计

### Agent 定义

Agent 是数字员工，与 t_employees（人类员工）并列，共同构成企业员工体系。

**核心属性**:
- `name/e_name`: 中英文名称
- `mode`: 服务模式（exclusive/shared/public/department）
- `config`: 模型配置 + 运行时配置 + 多模型协作配置
- `profile`: 个人事实与偏好
- `heartbeat`: 心跳配置

**运行时状态**（内存中）:
```typescript
interface AgentRuntime {
  // 基础信息
  sid: string;
  name: string;
  config: AgentConfig;
  
  // 运行时状态（不持久化）
  runtime: {
    status: 'idle' | 'running' | 'error';
    lastHeartbeat: Date;
    nextHeartbeat: Date;
  };
  
  // 内存缓存
  cache: {
    skills: Skill[];
    contacts: Map<string, ContactContext>;
  };
}
```

### Tool-based Routing 设计

Agent 通过三个内置 Tool 实现 LLM 自决策的任务路由：

#### Agent 层 Tools（3 个）

**1. orchestrator tool**
- 用途：处理需要多个 Skill 组合、有依赖关系或并行任务的复杂场景
- 参数：
  - `skills`: 需要使用的 Skill 名称列表（从系统提示中选择）
  - `taskDescription`: 任务描述和相关上下文

**2. executor tool**
- 用途：处理单一明确的 Skill 任务
- 参数：
  - `skillName`: 要执行的 Skill 名称
  - `taskDescription`: 任务描述和相关上下文

**3. handler tool**
- 用途：执行基础命令（read/write/exec）
- 参数：
  - `command`: 命令类型（read/write/exec）
  - `params`: 命令参数（file_path/content/command/cwd）

#### 工具层级关系

```
┌─────────────────────────────────────────────────────────────────┐
│                        Agent 层                                  │
│  Tools: [orchestrator, executor, handler]                       │
└─────────────────────────────────────────────────────────────────┘
          │
          ├──────────────────────────────────┐
          │                                  │
          ▼                                  ▼
┌─────────────────────────┐    ┌─────────────────────────┐
│   Orchestrator /        │    │       Handler           │
│   Executor              │    │  (直接执行基础命令)       │
│   Tools: [read, write,  │    │  - read: 读取文件        │
│           exec, ...]    │    │  - write: 写入文件       │
│   (默认包含基本工具)      │    │  - exec: 执行命令        │
└─────────────────────────┘    └─────────────────────────┘
```

#### 使用场景

| Tool | 适用场景 | 示例 |
|------|----------|------|
| handler | 简单的文件操作或命令执行 | "读取某个文件内容"、"执行一个命令" |
| executor | 单一 Skill 任务 | "生成一个 PDF 文档" |
| orchestrator | 多 Skill 协作任务 | "读取数据后生成报告并发送邮件" |

这样设计的优势：
- Agent 层职责清晰：路由决策 + 基础命令执行
- handler 提供快速的基础操作能力，无需启动 Orchestrator/Executor
- 复杂任务通过 orchestrator/executor 处理，保证上下文隔离
- **Skill 按需注入**：Orchestrator/Executor 只接收指定的 Skills，而非全部

#### Skill 注入策略

Agent 在调用 orchestrator/executor 时，只传递 LLM 选择的 Skills：

```
用户请求："用 pptx 生成报告"
    ↓
Agent 调用 executor tool，参数：skillName: "pptx"
    ↓
Executor 只接收 pptx skill，在 system prompt 中注入
    ↓
Executor 的 LLM 调用只看到 pptx skill 信息
```

**注入位置**：Skills 信息注入在 **system message** 中，而非 user message。

```
┌─────────────────────────────────────────┐
│ System Message                          │
│ ┌─────────────────────────────────────┐ │
│ │ # Task Executor                     │ │
│ │ ...                                 │ │
│ │ ## Available Skills                 │ │
│ │ ### pptx                            │ │
│ │ 生成 PowerPoint 演示文稿             │ │
│ └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
┌─────────────────────────────────────────┐
│ User Message                            │
│ 生成一个 Hello World PPT                │
└─────────────────────────────────────────┘
```

#### 工作流程

```
用户消息
    ↓
Agent 调用 LLM（带 orchestrator/executor/handler tools）
    ↓
LLM 根据用户意图选择合适的 tool
    ↓
┌─────────────────┬─────────────────┬─────────────────┐
│ orchestrator    │ executor        │ handler         │
│ (复杂任务)       │ (简单任务)       │ (基础命令)       │
├─────────────────┼─────────────────┼─────────────────┤
│ 多 Skill 协作    │ 单 Skill 执行    │ read/write/exec │
│ 任务编排         │ ReAct 循环       │ 直接返回结果     │
│ 并行/串行计划    │ 工具调用         │                 │
└─────────────────┴─────────────────┴─────────────────┘
    ↓
返回执行结果
```

#### 优势

| 方面 | 旧设计 | 新设计 |
|------|--------|--------|
| LLM 调用次数 | 2-3 次 | 1 次 |
| 复杂度判断 | 硬编码 + 额外 LLM | LLM 自决策 |
| 上下文隔离 | 部分 | 完全隔离 |
| 代码复杂度 | 高（多层判断） | 低（tool 路由） |
| 灵活性 | 低 | 高 |
| Agent 工具数 | 5+ | 3 |

### 多模型协作配置

Agent 支持配置多模型协作模式，用于处理复杂的语音交互场景：

```typescript
interface MultiModelCollaborationConfig {
  /** 是否启用多模型协作 */
  enabled: boolean;
  /** 语音识别模型实例ID */
  speechRecognitionInstanceId?: string;
  /** 主对话模型实例ID */
  mainModelInstanceId?: string;
  /** 语音合成模型实例ID */
  speechSynthesisInstanceId?: string;
  /** 是否启用流式协作（实验性） */
  enableStreaming?: boolean;
}
```

**协作流程**:
1. **语音输入**: 语音识别模型(STT) → 文本
2. **主对话**: 主模型处理文本 → 生成回复
3. **语音输出**: 语音合成模型(TTS) → 音频

### Agent 与员工的关系建立

员工通过 **WebUI** 访问 Agent，关系建立流程：

```
员工登录 WebUI
    ↓
认证：t_users → t_roles → t_permissions
    ↓
识别身份：t_employees → t_contacts (type='employee')
    ↓
建立通道身份：r_channel_contact (cradle:user-id)
    ↓
访问 Agent：通过 t_relationship 验证关系
```

**关系建立方式**：
